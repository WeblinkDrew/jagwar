- Pair: `@onlook/leads`'s `CandidateV1` and `packages/db/src/schema/leads`. Both can obey AD-4, AD-8, and the Zod-at-boundaries convention while independently choosing different field names, nullability, provenance cardinality, qualification-evidence shapes, or enum values. The spine does not name one canonical domain schema, prescribe the domain-to-persistence adapter, or require round-trip contract tests, so compliant discovery output can still be unreadable by qualification or project-context code.

- Pair: a Candidate producer and the `JagwarBusinessContextV1` renderer. The convention that unknown facts are represented by explicit "null/absence" permits two incompatible encodings, while AD-8 and AD-9 require explicit unknowns and omission of unknown claims. One unit can emit `null`, another can omit the field, and each can plausibly claim compliance. Select one tagged unknown/known representation and define its exact rendering behavior.

- Pair: the discovery evidence adapter and the verified-Lead persistence adapter. AD-8 permits policy-approved raw provider payloads "outside authoritative facts" but assigns no owner, storage location, reference type, redaction rule, access policy, or deletion contract to that evidence. One adapter can store provider JSON in PostgreSQL and another can store a blob URL; both comply, while provenance dereferencing, privacy, and retention behavior diverge.

- Pair: a tRPC admission procedure and a durable worker. A stable provider key derived from a newly created operation prevents repeated effects only within that operation; it does not prevent a retried admission request from creating a second operation with a second key. AD-7 and AD-12 do not define the uniqueness scope, canonical input hash, replay response, or payload-mismatch behavior for admission idempotency, so both units can be idempotent locally and still duplicate searches, projects, or sends globally.

- Pair: the PGMQ consumer and the operation repository. AD-6 and AD-7 require a visibility timeout, lease, and fencing token but do not define the claim algorithm or transition order. One worker can read PGMQ before acquiring the database lease, while another can acquire or renew a lease before hiding a message; both satisfy the prose but produce different crash, redelivery, stale-worker, and archive outcomes. Specify an atomic transition table and the exact read/lease/fence/commit/archive sequence.

- Pair: discovery and outreach handlers using `@onlook/durable-operation`. The package owns the state machines, but the spine gives no closed operation statuses, legal transitions, attempt lifecycle, retry classification, backoff calculation, attempt ceiling source, lease-expiry transition, or terminal-state semantics. Each handler can invent a compliant state machine, making the single durable substrate operationally plural.

- Pair: an external-effect adapter and its reconciliation handler. "Reconciliation path" is not a contract: one adapter may treat a timeout as retryable failure, while another may mark an unknown outcome and query the provider before retrying. Providers without native idempotency or lookup support are not addressed. Define adapter capability requirements, an external-effect receipt, an `unknown_outcome` state, and the conditions under which dispatch may or may not be repeated.

- Pair: the callback endpoint and the durable operation handler. AD-7 binds callbacks but does not specify provider-signature verification, replay protection, event identity, ordering, tenant lookup, or whether callbacks mutate authoritative operation state directly or enter through a durable inbox. Both a direct mutation and an inbox/enqueue design can obey the current rules while producing incompatible ordering and retry behavior.

- Pair: the policy-release service and a capability validator package. AD-5 places the closed `PolicyKind` in `@onlook/business-policy` and validators in independent capability packages, but does not define the public registry-composition seam, canonical JSON/hash algorithm, `(kind, schemaVersion)` uniqueness, or activation-time selection behavior. Two services can map different validators to the same kind/version or hash semantically identical payloads differently while satisfying every listed field requirement.

- Pair: a qualification decision writer and a later send-eligibility evaluator. The spine says policies are immutable and supersedable, but does not require every decision/effect to snapshot the exact policy-release ID and evaluated input version. One unit can evaluate the policy effective now and another the policy effective when the Lead was qualified; both are defensible under AD-5, yet audit and replay results diverge.

- Pair: the Lead fact store and a user-correction mutation. AD-8 prohibits generated guidance from updating verified facts without an explicit audited correction, but does not define fact-level identity, verification status, provenance multiplicity, correction lineage, conflict handling, or whether corrections replace or supersede evidence. Independent implementations can keep a mutable Candidate row or append fact revisions and both claim an audit trail, while downstream qualification and prompt composition see different facts.

- Pair: the prospect-project application service and the native project router. The protected-seam table anticipates extracting a canonical transaction from `project.ts`, but AD-9 does not explicitly make that approved extraction the only allowed integration seam. A downstream unit could instead recreate the project transaction in a new file or call a route-private client manager, satisfying the stated native lifecycle outcome while violating canonical mutation ownership. Mark the protected extraction as a blocking prerequisite and forbid alternate project-creation transaction implementations.

- Pair: the business-context serializer and the personalized-draft evidence checker. AD-9 specifies the fields and the PROMPT path but not the context's owning package/path, schema-version compatibility, canonical serialization, size/truncation limits, delimiter or prompt-injection treatment, selected-fact snapshot, or objective evidence predicate. Both units can be valid independently while disagreeing about which facts entered the prompt and whether the resulting draft passes.

- Pair: the Publication Reference creator and the outreach dispatcher. A completed deployment ID plus a public URL is not necessarily an immutable rendering of the exact publication if that URL can later serve republished content. "Version reference when available" permits one creator to omit version identity and another to require it; allowed deployment types and reachability/expiry checks are also undefined. Both dispatchers can send the snapshotted URL while failing the requirement to send the exact publication.

- Pair: the consent/compliance service and the outreach worker. No AD defines the required immediate pre-dispatch revalidation, its atomic relationship to the dispatch-start marker, the consent-evidence version, suppression-policy snapshot, or the decision recorded when consent changes between admission and execution. One unit can validate at enqueue time and another just before the provider call, and neither directly violates the current spine. This leaves the mandatory compliant-send invariant exposed to a time-of-check/time-of-use race.

- Pair: cost-observation writers and the existing Onlook usage authority. AD-11 allows additive observations but does not name their canonical table/API or explicitly prohibit writing a corresponding `usage_records` row before OD-14. One handler can write only an operation-linked observation while another can extend `usage_records` for the same action; both can argue that Stripe remains the commercial authority, yet reporting becomes a dual ledger. Define one observational write path, deduplication key, estimate-to-actual correction model, and an explicit no-commercial-record side effect.

- Pair: the activation projector and the send outcome model. AD-12 says projections are rebuildable, but no authoritative rebuild source or event/outbox transaction is selected. One projector can scan current aggregate tables, while another consumes events that may be emitted after commit; both follow the event convention and can disagree after a crash. Choose table-derived replay or a transactional outbox, and define checkpoint/idempotency semantics.

- Pair: the activation counter and the outreach result mapper. OD-7's acceptance-versus-delivery rule is deferred even though the first-release `5+2+1` proof requires one compliant successful Send. One unit can count provider acceptance and another can require delivery, so the same committed Send can both pass and fail release acceptance. This must remain an explicit release blocker or receive a provisional, versioned success definition before the vertical slice is certified.

- Pair: new `/leads`, `/pipeline`, and `/outreach` routes and the existing protected `/projects` shell. AD-13 requires thin server-first UI but does not specify the route group, authentication guard, subscription behavior, or shared navigation/layout boundary. One route can rely solely on protected tRPC while another duplicates the existing page-level gate; both preserve client-side non-authority but expose different unauthenticated and unsubscribed experiences and risk creating a second shell.

- Pair: two feature orchestration teams placing code under the proposed generic `apps/web/client/src/server/services/`. AD-4 rejects dumping packages, yet the structural seed provides a dumping directory without capability subpaths, public boundaries, or dependency-direction enforcement. Discovery and outreach can each create policy, operation, and persistence helpers there with overlapping ownership while their focused packages remain pure. Replace the generic seed with named capability service directories and a dependency matrix.

- Pair: Supabase Cron configuration and the bounded Next.js consumer. The spine does not define request authentication beyond one static secret, replay resistance, secret rotation, cron overlap behavior, batch/time budgets, per-kind execution limits, or the deployment timeout that bounds the Next.js route. Two environment configurations can both be "authenticated" and "bounded" yet differ enough to cause concurrent processing, replayed invocations, or route termination before lease completion.

- Pair: web-session database access and privileged internal-worker database access. AD-3 requires explicit authorization and RLS defense in depth, but does not specify the worker database role, owner-scoped repository query shape, composite owner/resource constraints, or how an operation's stored owner is authenticated rather than merely trusted. Both paths can call the same Drizzle repositories while only one is protected from a cross-owner reference inserted by a prior defect.
